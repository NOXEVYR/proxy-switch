流向 FlowSwitch {{PRODUCT_VERSION}}

完整解压并保留 app，双击 FlowSwitch.exe。使用已有锁定运行组件，无需下载运行时。

断网时：先在首页点击「开始断网排查」。客户端停止时预览启动 Clash；内核仍未运行则到原客户端检查。入口就绪后按结果预览恢复设置、检测 HTTPS，再验证实际程序。不会强制退出软件或启动独立入口。整理旧线路不能替代这一流程。

日常模式：打开后先看「当前系统代理」和管理方。Clash 正常使用时无需重新应用，也无需启动流向独立入口。流向不会后台抢回代理。

需要备用入口时：先在目标代理客户端连接 → 到「代理入口」选中并检测 → 回「网络切换」选择它 →「预览切换…」核对后确认。返回原入口使用相同步骤。客户端只开启 VPN 隧道、没有提供本地 HTTP 入口时，流向会保留现状并提示到原客户端核对模式；不会凭登记端口认定切换成功。

日常切换修改系统代理与新进程读取的用户代理变量，保留 NO_PROXY、程序专线和绑定；不会关闭正在运行的程序。已有连接及程序缓存可能继续使用原代理。首页「撤回上次切换…」只恢复仍归流向最近一次切换的设置；外部已改动或原入口不可用时，保留当前设置。

旧代理残留：主页或「程序线路」点击「检查旧代理残留」，结果按 PID 列出代理变量本机端口、监听与对应 TCP 连接/尝试。这些证据不等于程序采用该变量或账号成功；未知不判失效，不同但仍监听的入口可能是专线。仅显式读取支持的 Chromium/Electron、显式环境适配程序及已核验后台的代理摘要，不后台持续读取，排除已识别游戏/反作弊目录、Windows 系统目录及已登记代理客户端，不输出完整环境、凭据或命令行。

处理前保存工作，正常完整退出程序、托盘和相关后台，再点「退出后按当前代理启动…」预览并确认。仍在运行或身份不明时拒绝；只设置这次新进程环境，保留系统设置、持久变量、账号、快捷方式和已有专线。专线冲突时按提示回「程序线路」核对。启动后测试头像、登录或消息，再重新检查。CLI：powershell ProxySwitch.ps1 -CheckProxyResidue，可加 -Program "C:\应用目录\程序.exe" 单独检查。

高级功能：程序专线、网站规则和自动备用需要流向固定入口。首次进入会说明影响，由你明确选择。已配置独立分流时保留「统一切换」和服务恢复机制；不要为修复普通系统入口而直接开启独立入口。流向不修改第三方 TUN、守卫或节点。

为程序选择线路时，受支持的 Chromium/Electron 会接入稳定的独立本地地址。首次接入必须自行保存任务并完整退出原程序，再从流向“按此线路打开”或已接入的桌面入口重开。之后 A/B/直连只更换入口后的出口，遵守同一代理入口的联网子进程可一起改线。长连接需自行刷新，或预览后确认重连。

Qt 网页组件程序选线时，确认独立启动预览后，完整正常退出整组程序，再从流向“按此线路打开”。只控制遵循 Qt 参数的网页组件，不能保证原生服务、游戏 UDP 或登录成功。首次后台可保留其他代理的系统入口与用户变量；原桌面入口不自动绑定。

命令行/后台程序：选中程序 → 更多设置 → 启动与桌面入口 → 命令行 / 后台代理环境… → 选线并确认预览 → 正常退出整组目标后按此线路打开。只影响新启动且会读取代理变量的请求，不写全局环境。已有 Codex、其他终端及忽略代理的 OAuth 不保证覆盖。

外部 VPN/TUN 可与单程序独立启动入口共存，但会阻止统一接管。“应用代理已关闭”不是物理直连，选直连也不保证绕过 VPN。流向读取实际网卡及路由证据，不代改其他软件开关。

网站规则可让同一浏览器的不同域名分别直连/代理。程序范围优先于全局范围，更具体的域名优先；统一切换保留网站例外。只填写域名，不填写登录链接。

关闭窗口默认驻留右下角系统托盘，代理继续运行。双击托盘图标恢复。只有“停止代理服务并退出”才恢复仍归属本工具的网络设置并停止内核。旧版更新前须通过托盘停止服务，保留用户目录下 .proxyswitch 数据与原程序目录。

桌面程序入口会交给常驻主窗口启动。代理未就绪不会假装已接管；启动成功后的记录/观察失败单独提示，不会重复启动。没有适配或自行缓存旧上游地址的应用不能仅靠改系统代理强制迁移；不结束用户应用。

“按此线路打开”会检查该程序自己的出口和固定入口，默认线路故障不应阻止正常专线。全部上游离线时保留配置并拒绝打开；明确直连网站例外仅代表这些例外可能可用，不代表所有网站恢复。

系统显示直连但程序变量仍指向已停止的 Clash 时，先用首页「开始断网排查」确认是否应启动原客户端。只有明确要放弃旧入口时，再到「检查与维护 → 连接检查 → 查看并修复…」处理；只清理已确认失效的变量，保留其他有效、未知变量及 NO_PROXY。NO_PROXY 广泛绕过只提示，不自动删除。已运行应用的环境不会自动刷新，需要自行保存工作后正常重开。

下次遇到软件打不开：先在「程序线路」选中该软件，点击「排查此程序网络」。不知道影响范围时，在首页点「开始断网排查」，或到「检查与维护 → 连接检查 → 开始网络检查」。结果窗口会区分系统设置、当前入口、代理通路和目标程序连接，给出证据与下一步；没有观察到请求时，在软件中重试后点击「重新检查」。底层信息在「检查详情」，无需先翻操作日志。

检查本身不改网络设置，也不创建代理启动快捷方式。结果中只有存在现有可处理项时才启用「整机修复预览…」；确认前会显示整机影响。已发现记录问题不等于已经确定无法联网的原因，端口监听和 HTTPS 回应也不等于账号登录成功。

停止服务时如果外部设置仍引用流向主入口或程序入口，会保留后台并提示处理；请在写入设置的代理软件中换线后再停止，避免其他应用连接死入口。

连接列表只代表当前 TCP 观察。短时连接、UDP/QUIC、独立隧道可能不在表中；未观察到连接不等于断网，读取失败不等于未运行。浏览器显示登录成功、HTTPS返回响应，都不能代替客户端换取令牌及完成登录的验收。

保存线路与实际连接不同：左列是保存的目标，右列是观察到的连接。程序升级导致旧路径失效时，点击「修复路径后改线…」预览修复；服务明确停止时可只更新记录，不启动代理。要取消已停用专线、让程序使用 Windows 当前系统代理，到「更多设置 → 记录与详情 → 使用系统代理（取消已停用专线）…」。它与跟随流向默认出口的「跟随统一线路」不同，操作前会核验服务、入口及关联记录。

隔离测试覆盖真实本地内核和父子程序，另一台电脑的真实应用、浏览器回调及账号登录仍需实测。请保留旧版与本机备份。

登录排查（3.9.0 起适用，后续版本保留）：右键启动器，先检查并补齐已验证的整组规则；完整退出游戏与启动器后，可选择干净环境启动。直连登录对照须明确确认，会临时影响当前用户系统代理，最长五分钟；可在检查与维护 → 维护与恢复 → 结束对照并恢复中提前结束。恢复会保留其他软件后来修改的设置。恢复失败会保留快照并提示，不能视为登录成功。

任务栏图标：新版的 EXE、窗口和快捷方式使用同一双入口标识。正常退出旧版后，运行创建桌面快捷方式，再打开新版。旧固定入口可取消固定后重新固定；程序不会重启资源管理器或清空系统图标缓存。

3.9.4 应用内更新
检查与维护 → 软件与记录可手动检查或关闭自动检查。自动检查延迟到界面就绪，失败退避。
官方程序差异不超过 50 MiB 时可暂存；安装需明确确认，先正常恢复系统代理并停止自有服务。
不会结束其他应用、不自动开启 TUN、不覆盖配置或凭据。恢复失败保留窗口。
安装重启后默认只读。已有专线时，到代理入口→备用与服务→使用流向独立入口启动服务并保留专线；需要所有程序跟随同一路线时才统一切换。运行时或文件布局变化需手动完整包。
更新备份/事务保存在数据目录 updates 内，请勿在更新或恢复期间删除。

普通游戏等程序：程序线路→选中程序→设置此程序线路→选择直连或代理，首次选择后直接弹出接入预览，核对并确认。已有引擎规则需要重新接入时，再点应用线路并检查。保留其他专线和有效备用；系统入口被其他代理改写时，不必先统一切换。旧连接请在程序内重试或正常退出重开；VPN/TUN或内置代理不保证覆盖。

已配置服务尚未启动时：代理入口→备用与服务→使用流向独立入口，明确启动并保留专线，再回程序线路应用。默认代理暂停时仍可应用已核验的明确直连/健康专线；其他跟随默认的程序不因此恢复。


多代理/VPN 共存：先选程序 → 排查此程序网络 → 处理办法。程序专线检测自己的入口，系统检查独立显示；报告提供程序线路、路径修复、旧连接预览与干净环境启动的入口。程序仍运行时先保存并完整正常退出，不会自动结束它。
「直连」只是不使用指定上游代理，不能保证绕过外部 VPN 路由。请在原 VPN 客户端核对是否提供绕过规则；流向不代改第三方 TUN、DNS、hosts 或系统路由。

入口仍监听但一直超时：在「排查此程序网络」查看当前观察到的外部代理入口对照。家族观察不完整时，此对照只覆盖已核验成员，不代表全程序。固定 HTTPS 目标均超时时，先核对原代理/VPN 的连接和节点，再重测同一入口。浏览器正常、HTTP 401 或端口打开，都不能单独证明模型请求或登录正常。
开机时程序早于代理：通过流向按保存代理线路打开会等待入口健康与真实请求检查；普通桌面启动不受这项等待管理。流向不自动结束当前程序或重连第三方 VPN。
